2026-10-05 に、機械器具点検・清掃記録・薬品管理・添加物管理を書き出したときの仕組みと決まりです。
書き出し先は Figma の `Ver.4.0_機械器具点検、清掃記録`（fileKey `xj2PtvuuIe5O8PcAvna3Hi`）の「📺 AI書き出し」ページ（page id `7688:98558`）。

## 出力の決まり（ユーザーと決めたこと）

- **静止画は作らない。** 編集できるレイヤー（オートレイアウト）だけを出す
- フレーム名は「機能 › 帳票 › 画面」。開いた状態は末尾に `（ポップアップ：○○）` `（ダイアログ：○○）` `（パネル：○○）`
- **帳票ごとに 1 列**。列は左から 機械器具点検 → 清掃記録 → 薬品管理 → 添加物管理。新しい帳票は一番右に足す
- 各列に次の 7 セクションを縦に並べる（この順）。同じ種類のセクションは列をまたいで同じ高さにそろえる
  1. （Admin）帳票管理_<帳票>（新規登録・点検予定・確認項目の設定など。保管場所管理がある帳票は行を足す）
  2. （App）帳票一覧_<帳票>（記録する。点検予定がある帳票は「点検予定」の行を足す）
  3. （App）確認待ち_<帳票>（1枚目は帳票一覧、2枚目は確認待ち）
  4. （Admin）承認申請管理_<帳票>
  5. （App）確認待ち_差し戻し_<帳票>（1枚目は帳票一覧）
  6. （App）進捗一覧_<帳票>
  7. （Admin）データ検索_<帳票>
- セクションの色：Admin は薄い青 `#E8F0FC`、App は薄い緑 `#E6F6EB`。左外に札（管理画面（Admin）／アプリ画面（App）・機能名・中身の説明）、列の上に帳票名の大見出し
- セクションの中は操作の順に左から。管理画面 6 枚・アプリ 8 枚で折り返す。共通の入口の画面（帳票選択・帳票一覧・確認待ち・承認申請管理・進捗一覧と絞り込み条件・データ検索の帳票選択）は既存の列から複製
- 撮る画面：画面設計の `SCREENS` の帳票の画面 ＋ SPEC の ops にあるポップアップ・ダイアログを開いた状態 ＋ ユースケース（CASES）の途中の画面（確認者を選んだ後の中身・差し戻しの修正と対応完了・進捗一覧から入る記録入力〜提出完了など）
- React に無い画面を頼まれたら、元になる画面の DOM を書き換えて撮る（例：清掃記録の点検予定は `toclean.js`）。先にユーザーに確認する

## 書き出した後に必ず当てる直し（figma-builder.js に入っている）

- アプリのヘッダーに背景色（#F1EFEA）を付けて下の影を出し、ヘッダーを手前にする
- ポップアップ・ダイアログは幕ごと画面の一番手前へ移し、画面全体の大きさの中央揃えにする（本体は Hug）
- 年月の選択・実施日のカレンダーは一番手前へ出し、はみ出す分だけ中身を上にスクロール
- 管理画面のタイトルの帯は 88px・上下中央。帯の中で縦に伸びたボタン（ダウンロード 40×40・＋新規登録 120×40）を戻す
- 「コメントを残す」は緑にする（React は未入力だとグレーの非活性。Figma は確定デザインどおり緑。`greenComment()`）
- 承認ステータスの三角の下矢印は白（`button: 承認待ち` の中のベクター）
- 点検予定の保存完了は、提出完了と同じデザイン（上寄せ 24/32、ボタン 360×64・文字 20px）
- **画面は中身の下まで全部出す**（2026-10-05 にユーザー指定）。組み立てのあと `expand-full-height.js` を列ごとに当てる：スクロール部分を中身に合わせて伸ばし、サイドメニュー・左レールも伸ばす。ポップアップの画面は、幕を全体にかけて本体は最初の表示範囲（760／1024）の中央に残す。年月の選択はスクロールさせた状態なので伸ばさない
- 確定デザインとの比較で足した画面は、各セクションの一番下に「確定デザインとの比較で追加した画面」の行を作って並べた（2026-10-06）。共通の画面（絞り込み条件・差し戻しのある一覧・未点検・アコーディオンを閉じた状態）は 4 列それぞれに置く
- 伸ばしたあとは、列をまたいで同じ種類のセクションの高さをそろえ、下の行（セクションと左の札）をずらす。左の札（ラベル：…）は必ず セクションの y + 120 に置き直す（ずらし忘れて別の行の横に出ていたことがある）。セクションの間は 500px

extract.js 側で直してあること：文字は行の高さで枠を取る／CSS の重なり順（位置指定のある要素を手前）／`oklab()` などの色を canvas で RGB に直す／CSS mask のアイコンは背景色で塗る／SVG の `var(--…)` を実際の色にする／data URI の SVG は `getAttribute('src')` で全部読む。

## 手順

1. `node .claude/serve.cjs` を立ち上げておく（`http://127.0.0.1:8791/react/?frame=1#<hash>` を撮る）
2. 撮る画面の一覧を作る（`plan-example.py` が見本。id・name・pf(admin/app)・hash・steps）。steps は `act.js` の操作（`click` 文字で押す／`sel`／`pick` ポップアップの最初のカード／`eval`／`optional`）
3. `PLAN=plan.json PORT=<重ならない番号> node cdp2.mjs <id>` で 1 画面ずつ取り出す（`json2/<id>.json` と `shots2/<id>.png`）。並列にするときは PORT を必ず別々に（同じ PORT だと別の画面が混ざる）
4. 撮った画像を一覧にして、ねらった状態か目で確かめる
5. `python3 topng.py json2/<id>.json png2/<id>.png` でデータを画像に詰める → Figma MCP の `upload_assets`（60 件まで）→ submitUrl に curl で POST して imageHash を得る
6. `figma-builder.js` の先頭に `const S=[[hash, name, x, y, 一時フレームid, セクションid, 'admin'|'app'], …];` を付けて `use_figma` で 8 枚ずつ組み立てる（一時フレームは組み立て後に消える）
7. 列とセクションを作る・既存の行を下げる・共通画面を複製する
8. 文字は Noto Sans JP で入る。最後にユーザーに `figma-hiragino` のプラグイン（`hiragino-plugin-*.json/js` を manifest.json / code.js として置いてインポート）を実行してもらい、ヒラギノ角ゴ ProN（300〜500→W3、600〜→W6）に置き換える

## 注意

- Figma 側（use_figma）はユーザーの Mac の外で動くので、ヒラギノを読み込めない。ヒラギノになった文字は大きさも変えられないので、作り直すときは Noto で作り直してプラグインをもう一度
- use_figma のコードは 50,000 文字まで。データは画像に詰めて upload_assets で渡す（getImageByHash はページを切り替えてから）
- 一時的な作業ファイルは scratchpad に置く。ここにあるのは道具だけ
